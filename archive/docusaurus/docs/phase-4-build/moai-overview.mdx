## What is MOAI?

The **Milestone-Oriented AI Integration (MOAI)** framework structures the Build phase into manageable, verifiable milestones. Each milestone has clear deliverables, quality gates, and acceptance criteria.

:::info Why Milestones Matter
Large implementation projects fail for predictable reasons:
- **Scope creep** — features grow beyond what was planned
- **Context loss** — AI loses track of the bigger picture over long sessions
- **Quality drift** — standards erode as deadlines approach

MOAI addresses these by:
1. **Fixed scope per milestone** — Each milestone has explicit, unchanging deliverables
2. **Fresh context per milestone** — Start each milestone with clean context and the Build Contract
3. **Quality gates** — No milestone is complete until all quality criteria pass
:::

## The Integration Flow

MOAI-ADK (Methodology for Organized AI-Driven Development Kit) structures AI-assisted implementation through SPEC-First Development, EARS Requirements, TDD Workflow, and Documentation Sync.

```
HANDBOOK + MOAI INTEGRATION
===========================

Design Brief      ----+
UX Package        ----|---> Build Contract ---> SPEC ---> TDD Cycle
UI System         ----|                              |
Architecture      ----+                              v
                                              Tested Code + Docs
```

## The 11-Milestone Structure

The Build phase is organized into 11 milestones across three checkpoints:

### Foundation (M1-M4)
| Milestone | Focus | Deliverables |
|-----------|-------|--------------|
| M1 | Project Foundation | Project structure, tooling, configuration |
| M2 | Database Schema | Data model, RLS policies, migrations |
| M3 | Core API | API routes, validation, error handling |
| M4 | UI Shell | Layout components, navigation, routing |

**Checkpoint 1** — Verify foundation before building features

### Features (M5-M7)
| Milestone | Focus | Deliverables |
|-----------|-------|--------------|
| M5 | Authentication | Auth flows, protected routes, sessions |
| M6 | Core Feature | Your product's main functionality |
| M7 | Admin Console | Admin dashboard, user management |

**Checkpoint 2** — Verify features before polish

### Polish (M8-M11)
| Milestone | Focus | Deliverables |
|-----------|-------|--------------|
| M8 | Advanced Features | Secondary features, integrations |
| M9 | Payments | Stripe integration, subscriptions |
| M10 | Polish | UX refinements, performance |
| M11 | Pre-launch | Testing, documentation, deployment prep |

## Core Principles

### 1. SPEC-First Development

Every feature starts with a SPEC document that defines:
- Requirements in EARS format
- Test cases in GIVEN-WHEN-THEN format
- Acceptance criteria
- Build Contract references

### 2. TDD Workflow

Implementation follows the RED → GREEN → REFACTOR cycle:
- **RED:** Write failing tests from SPEC test cases
- **GREEN:** Write minimum code to pass tests
- **REFACTOR:** Improve code quality while tests stay green

### 3. Quality Gates

Each milestone ends with verification:
- All tests pass
- No TypeScript errors
- Linting passes
- Security requirements met

## Getting Started

Before starting any milestone:

1. **Create the Build Contract** — Use the Build Contract prompt (Chapter 21) to synthesize your design artifacts
2. **Set up SPEC folder structure** — Create `docs/specs/` in your project root
3. **Configure testing framework** — Install Jest and React Testing Library:
   ```bash
   npm install -D jest @testing-library/react @testing-library/jest-dom
   ```
4. **Create CLAUDE.md** — Set up your AI context file following the template
