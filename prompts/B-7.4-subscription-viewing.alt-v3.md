```text

  
  ROLE
Full-Stack Developer building subscription visibility for admin console.

CONTEXT
User management is complete (Prompt 7.3).
Building read-only subscription viewing for Phase 1.
Manual billing adjustments will come in Phase 2 (Post-MVP).

OBJECTIVE
Create subscription overview and detail viewing.

REQUIREMENTS

1. Subscriptions list page (src/app/admin/subscriptions/page.tsx):
- Overview metrics: Total active, MRR, Churn this month
- Table of subscriptions with pagination
- Columns: User, Plan, Status, Started, Renews, MRR
- Filter by: plan, status (active, canceled, past_due)
- Click row to go to user detail (subscription shown there)

2. Subscription queries (src/lib/admin/queries/subscriptions.ts):
- getSubscriptions(options): Paginated, filtered list
- getSubscriptionStats(): MRR, counts by status, churn rate
- getSubscriptionsByPlan(): Breakdown by plan type
- getRecentChanges(): New, canceled, upgraded in last 7 days

3. MRR calculation helper (src/lib/admin/utils/mrr.ts):
- calculateMRR(subscriptions): Sum of monthly values
- Handle annual plans (divide by 12)
- Format as currency

4. Subscription components (src/components/admin/subscriptions/):
- SubscriptionTable: Sortable rows
- SubscriptionFilters: Plan, status filters
- MRRCard: Display MRR with trend indicator
- SubscriptionStatusBadge: Colored status indicator

5. Add subscription info to user detail:
- Current plan name and price
- Status with colored badge
- Start date and next renewal date
- Link to Stripe customer portal (if applicable)

QUALITY STANDARDS
MRR calculation handles edge cases (trials, discounts)
Status badges use consistent colors
No sensitive payment data displayed (no card numbers)
Queries efficient with proper indexes

DELIVERABLES
1. src/app/admin/subscriptions/page.tsx
2. src/lib/admin/queries/subscriptions.ts
3. src/lib/admin/utils/mrr.ts
4. src/components/admin/subscriptions/ (all components)
5. Updated user detail page with subscription section

VERIFICATION
1. Subscriptions page shows list and metrics
2. MRR calculation matches expected value
3. Filter by status shows correct results
4. User detail shows subscription info
5. No card numbers or sensitive data visible
```
