```text

  
  ROLE
Security-focused Full-Stack Developer implementing admin access control.

CONTEXT
Project: {{productName}}
Authentication is working (Milestone 5 complete).
Profiles table has role column with values: user, admin, super_admin.
Database has is_admin() helper function.

OBJECTIVE
Implement server-side admin access control.

REQUIREMENTS

1. Create admin auth utilities (src/lib/admin/auth.ts):
- getAdminUser(): Fetches current user, returns null if not admin
- requireAdmin(): Throws error if not admin, for use in server actions
- requireSuperAdmin(): Throws error if not super_admin
- isAdmin(role: string): Type guard helper
- isSuperAdmin(role: string): Type guard helper

2. Update middleware (src/middleware.ts):
- Add matcher for /admin/* routes
- For admin routes: verify user is authenticated
- For admin routes: verify user has admin or super_admin role
- Redirect non-admins to /dashboard with error message
- Allow admins to continue to admin routes

3. Create admin types (src/types/admin.ts):
- AdminUser type extending base User with role
- AdminRole enum: 'user' | 'admin' | 'super_admin'
- AdminAuditLog type
- AdminNote type

4. Create audit logging utility (src/lib/admin/audit.ts):
- logAdminAction(action, targetType, targetId, details): Logs to admin_audit_logs
- Uses service role client (bypasses RLS)
- Captures admin_id from session
- Captures IP address from headers if available

QUALITY STANDARDS
Role check happens server-side, never trust client
Middleware runs on every admin route request
Audit logging is fire-and-forget (doesn't block response)
No admin role information exposed to non-admins
Error messages don't reveal admin route existence to non-admins

DELIVERABLES
1. src/lib/admin/auth.ts
2. src/lib/admin/audit.ts
3. src/types/admin.ts
4. Updated src/middleware.ts

VERIFICATION
1. As regular user: Visit /admin → redirected to /dashboard
2. As admin user: Visit /admin → allowed (404 ok, route doesn't exist yet)
3. Test requireAdmin() throws for non-admin
4. Test audit logging creates record in admin_audit_logs
```
