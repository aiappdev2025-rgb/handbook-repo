## Why Philosophy Before Screens?

Before diving into screen specifications, you need principles that guide decisions. Without them, every screen becomes a debate, and the product feels inconsistent.

:::info The Invisible Interface
Good design is invisible. Users should accomplish their goals without thinking about the interface. Every screen should have a clear purpose, every element should earn its place, and every interaction should feel natural.
:::

## The Five Core Principles

These principles should guide every design decision in your product:

### 1. Clarity Over Cleverness

Obvious is better than innovative. Users shouldn't have to think about how to use your product.

**Apply when:**
- Choosing between a "creative" navigation and a standard one → Choose standard
- Deciding on icon-only vs icon+label → Add the label
- Picking between custom components and platform conventions → Use conventions

### 2. Progressive Disclosure

Show what's needed, hide complexity. Don't overwhelm users with options they don't need yet.

**Apply when:**
- Designing forms → Show required fields first, optional later
- Building dashboards → Show key metrics prominently, details on demand
- Creating settings → Group by frequency of use, hide advanced options

### 3. Consistent Patterns

Same action, same behavior everywhere. Users learn once, apply everywhere.

**Apply when:**
- A user deletes something → Same confirmation pattern everywhere
- A form submits → Same success/error pattern everywhere
- Navigation changes → Same transition pattern everywhere

### 4. Forgiving Design

Easy to recover from mistakes. Undo, confirm destructive actions, provide clear error messages.

**Apply when:**
- User deletes something important → Provide undo or require confirmation
- Form submission fails → Preserve entered data, show specific errors
- User navigates away → Save drafts automatically

### 5. Performance as Feature

Fast feels professional. Every interaction should feel instant.

**Apply when:**
- Loading data → Show skeletons or spinners immediately
- Processing actions → Provide immediate feedback, process in background
- Navigating → Use optimistic updates where safe

## Applying the Principles

Use this decision framework when making design choices:

| Question | Good Answer |
|----------|-------------|
| Does this feature earn its place? | Solves a real user need |
| Is the path obvious? | No instructions needed |
| Are there unnecessary steps? | Each step has clear purpose |
| What happens on error? | Clear message, recovery path |
| What about empty states? | Helpful guidance, not just "No data" |

## Document Your Principles

Create a short principles document that you can reference:

```markdown
## Our Design Principles

1. **Clarity over Cleverness** - When in doubt, be obvious
2. **Progressive Disclosure** - Show complexity gradually
3. **Consistent Patterns** - Same action, same behavior
4. **Forgiving Design** - Easy to undo, hard to break
5. **Performance as Feature** - Fast is a feature, slow is a bug
```
