## The Core Principle

**Claude Chat** (web interface) is optimized for **exploration and document creation**.

**Claude Code** (CLI) is optimized for **codebase-aware implementation**.

The transition point is the **Build Contract** - the document that bridges design to implementation.

## Phase-by-Phase Tool Recommendations

| Phase | Activities | Recommended Tool | Why |
|-------|------------|------------------|-----|
| **Phase 1: Validate** | Market research, validation, opportunity scoring | Claude Chat | Exploration, no codebase yet |
| **Phase 2: Design** | Design Brief, UX Package, UI System | Claude Chat | Document creation, iteration |
| **Phase 3: Architect** | Architecture decisions, Build Contract | Claude Chat | Planning, no implementation yet |
| **Setup** | Create repo, CLAUDE.md, docs/ folder | Terminal + Claude Code | Repository initialization |
| **Phase 4: Build** | SPEC creation, TDD, implementation | Claude Code | Codebase-aware development |
| **Phase 5: Launch** | QA testing, deployment, monitoring | Claude Code | Working with live systems |

## The Build Contract Transition

The Build Contract is the **critical transition point**. It:

1. **Consolidates all design artifacts** into a single reference
2. **Defines vocabulary** that maps to code
3. **Specifies all screens, components, and APIs**
4. **Provides quality standards** for implementation

:::tip The Transition Moment
Once you have a Build Contract, you're ready to switch to Claude Code. Don't start Claude Code without it - you'll lack the context needed for consistent implementation.
:::

## Claude Chat Strengths

Use Claude Chat (web interface) for:

- **Exploration**: Brainstorming, research, ideation
- **Document creation**: Design briefs, UX packages, architecture docs
- **Iteration**: Refining ideas through conversation
- **Long-form content**: Specifications, technical writing
- **Visual review**: Looking at diagrams, UI mockups (via attachments)

### Example Claude Chat Tasks

```
"Help me validate this SaaS idea for real estate agents"
"Create a UX flow for the photo upload feature"
"Design the database schema for user subscriptions"
"Generate the Build Contract from these design documents"
```

## Claude Code Strengths

Use Claude Code (CLI) for:

- **Implementation**: Writing actual code files
- **Codebase awareness**: Understanding existing code structure
- **File operations**: Creating, editing, organizing files
- **Testing**: Running tests, debugging issues
- **Git workflow**: Commits, branches, version control
- **Build processes**: Running builds, checking for errors

### Example Claude Code Tasks

```
"Implement the login page based on SPEC-AUTH-001"
"Create the PhotoUpload component with drag-and-drop"
"Fix the TypeScript error in the user service"
"Run the test suite and fix any failing tests"
```

## Common Mistakes

### Starting Claude Code Too Early

**Mistake**: Jumping into Claude Code before finishing design.

**Problem**: Without a Build Contract, you'll make inconsistent decisions, backtrack frequently, and waste context on re-explaining requirements.

**Solution**: Complete Phases 1-3 in Claude Chat first. Generate the Build Contract before touching Claude Code.

### Staying in Claude Chat Too Long

**Mistake**: Continuing to design and plan when you should be building.

**Problem**: Analysis paralysis. Perfect is the enemy of good. You'll never start implementing.

**Solution**: Once you have a Build Contract, switch to Claude Code. You can refine in parallel with implementation.

### Using Claude Code for Design Documents

**Mistake**: Trying to create UX flows or architecture diagrams in Claude Code.

**Problem**: Claude Code is optimized for code, not prose. The CLI interface makes document iteration awkward.

**Solution**: Use Claude Chat for all design documents, then copy the final versions into your repo.

## Hybrid Workflows

Sometimes you need both tools in the same session:

| Situation | Workflow |
|-----------|----------|
| **Need to research while coding** | Keep Claude Chat open in browser for research, Claude Code in terminal for implementation |
| **Found a design gap during build** | Document the gap, continue implementing what you can, update Build Contract in Claude Chat later |
| **Complex debugging** | Use Claude Code for code changes, Claude Chat for explaining the problem and exploring solutions |
