## Recommended Stack

For AI SaaS applications, this stack optimizes for developer experience and cost efficiency:

| Service | Provider | Purpose | Cost |
|---------|----------|---------|------|
| **Hosting** | Vercel | Frontend + API routes | Free tier available |
| **Database** | Supabase | PostgreSQL + Auth + Storage | Free tier available |
| **AI** | Anthropic | Claude API | Pay-per-use |
| **Payments** | Stripe | Subscriptions | 2.9% + $0.30 |
| **Email** | Resend | Transactional email | Free tier available |
| **Analytics** | PostHog | Product analytics | Free tier available |

```json
// vercel.json
{
  "framework": "nextjs",
  "regions": ["iad1"],
  "env": {
    "NEXT_PUBLIC_SUPABASE_URL": "@supabase-url",

  }
}
```

## Supabase Setup

### Project Creation
1. Create project at supabase.com
2. Note the project URL and anon key
3. Run initial migration (from Chapter 14)

### Required Extensions
```sql
-- Enable required extensions
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";
```

### Storage Buckets
```sql
-- Create storage bucket for user uploads
INSERT INTO storage.buckets (id, name, public)
VALUES ('user-uploads', 'user-uploads', false);

-- RLS for storage
CREATE POLICY "Users access own uploads"
  ON storage.objects FOR ALL
  USING (auth.uid()::text = (storage.foldername(name))[1]);
```

## Environment Variables

Document all required environment variables:

| Variable | Description | Where to Get |
|----------|-------------|--------------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL | Supabase dashboard |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key | Supabase dashboard |
| `SUPABASE_SERVICE_ROLE_KEY` | Service role key (server only) | Supabase dashboard |
| `ANTHROPIC_API_KEY` | Claude API key | Anthropic console |
| `STRIPE_SECRET_KEY` | Stripe secret key | Stripe dashboard |
| `STRIPE_WEBHOOK_SECRET` | Webhook signing secret | Stripe dashboard |

:::warning Never Expose Secrets
Keys starting with `NEXT_PUBLIC_` are exposed to the browser. Never prefix sensitive keys like `SUPABASE_SERVICE_ROLE_KEY` or `STRIPE_SECRET_KEY` with `NEXT_PUBLIC_`.
:::
