## Environment Strategy

| Environment | Purpose | Database | URL |
|-------------|---------|----------|-----|
| **Development** | Local development | Local or dev Supabase | localhost:3000 |
| **Staging** | Pre-production testing | Staging Supabase | staging.yourapp.com |
| **Production** | Live application | Production Supabase | yourapp.com |

## Environment Files

Create environment-specific files:

```
.env.local          # Local development (gitignored)
.env.development    # Shared dev defaults
.env.staging        # Staging configuration
.env.production     # Production configuration
.env.example        # Template with all required vars
```

### .env.example

```bash
# App
NEXT_PUBLIC_APP_URL=http://localhost:3000

# Supabase
NEXT_PUBLIC_SUPABASE_URL=your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# AI
ANTHROPIC_API_KEY=your-api-key

# Payments
STRIPE_SECRET_KEY=your-stripe-key
STRIPE_WEBHOOK_SECRET=your-webhook-secret
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=your-publishable-key
```

### .env.local (Local Development)

```bash
# Copy from .env.example and fill in dev values
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=https://xxx-dev.supabase.co
# ... etc
```

:::warning Git Ignore
Never commit `.env.local` or any file with real secrets. Only commit `.env.example` with placeholder values.
:::

## Vercel Environment Configuration

Configure environments in Vercel dashboard:

1. Go to Project Settings → Environment Variables
2. Add variables for each environment:

| Variable | Development | Staging | Production |
|----------|-------------|---------|------------|
| `NEXT_PUBLIC_SUPABASE_URL` | dev-url | staging-url | prod-url |
| `SUPABASE_SERVICE_ROLE_KEY` | dev-key | staging-key | prod-key |

## Multiple Supabase Projects

For proper isolation, create separate Supabase projects:

```
yourapp-dev     → Development
yourapp-staging → Staging
yourapp-prod    → Production
```

Apply the same migration to all environments:

```bash
# Apply migrations to each project
supabase db push --project-ref your-dev-ref
supabase db push --project-ref your-staging-ref
supabase db push --project-ref your-prod-ref
```

## Environment Detection

Detect environment in your code:

```typescript
// lib/env.ts
export const ENV = {
  isDev: process.env.NODE_ENV === 'development',
  isStaging: process.env.NEXT_PUBLIC_APP_URL?.includes('staging'),
  isProd: process.env.NODE_ENV === 'production' &&
          !process.env.NEXT_PUBLIC_APP_URL?.includes('staging'),
};

// Usage
if (ENV.isDev) {
  console.log('Debug info:', data);
}
```

## Branch-Based Deployments

Configure Vercel for automatic deployments:

| Branch | Environment | URL |
|--------|-------------|-----|
| `main` | Production | yourapp.com |
| `staging` | Staging | staging.yourapp.com |
| `*` (other) | Preview | random-id.vercel.app |
