## What is an ADR?

An Architecture Decision Record captures:
- **What** decision was made
- **Why** this option was chosen
- **What** alternatives were considered
- **What** the consequences are

## ADR Template

Create ADRs in `docs/adr/`:

```markdown
# ADR-001: [Short Title]

## Status
Accepted | Proposed | Deprecated | Superseded by ADR-XXX

## Context
What is the issue that we're seeing that motivates this decision?

## Decision
What is the change that we're proposing and/or doing?

## Alternatives Considered

### Option A: [Name]
- Pros: ...
- Cons: ...

### Option B: [Name]
- Pros: ...
- Cons: ...

## Consequences

### Positive
- What becomes easier?

### Negative
- What becomes harder?

### Risks
- What could go wrong?

## References
- Links to relevant documentation, discussions, or research
```

## Example ADR

```markdown
# ADR-001: Use Supabase for Authentication

## Status
Accepted

## Context
We need authentication for our SaaS application. Options include
building custom auth, using NextAuth.js, or using Supabase Auth.
We're already using Supabase for the database.

## Decision
Use Supabase Auth for all authentication needs.

## Alternatives Considered

### Option A: Custom Authentication
- Pros: Full control, no vendor lock-in
- Cons: Security risk, significant development time

### Option B: NextAuth.js
- Pros: Flexible, many providers
- Cons: Additional dependency, separate from database

### Option C: Supabase Auth (Chosen)
- Pros: Integrated with database, RLS support, social providers
- Cons: Vendor lock-in to Supabase

## Consequences

### Positive
- RLS policies can reference auth.uid() directly
- No separate auth service to maintain
- Social login providers included

### Negative
- Migration away from Supabase becomes harder
- Limited customization compared to custom auth

### Risks
- Supabase pricing changes could affect costs
- Mitigation: Auth data is exportable

## References
- Supabase Auth docs: https://supabase.com/docs/guides/auth
```

## When to Write ADRs

Write an ADR when:

| Decision Type | Example |
|---------------|---------|
| **Technology choice** | "Use React Query vs SWR" |
| **Architecture pattern** | "Use server components vs client" |
| **Integration approach** | "How to integrate Stripe" |
| **Security decision** | "Token storage approach" |
| **Breaking convention** | "Why we're not using X" |

## ADR Folder Structure

```
docs/
├── adr/
│   ├── 001-use-supabase-auth.md
│   ├── 002-choose-tailwind-over-css-modules.md
│   └── 003-server-components-for-data-fetching.md
```
