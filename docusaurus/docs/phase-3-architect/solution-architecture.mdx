## What is Solution Architecture?

The Solution Architecture bridges design artifacts with implementation. It translates product requirements into technical decisions: which technologies to use, how components interact, what the data model looks like, and how security is handled.

:::warning Critical for Implementation
Creating this document before coding prevents costly mid-project pivots. Without it, Claude Code will make ad-hoc technical decisions that may conflict with each other.
:::

## Architecture Document Structure

Your architecture document should cover eight sections:

### 1. System Overview
- Architecture diagram (components and connections)
- Component responsibilities
- Data flow between services

### 2. Database Schema
- Tables with columns and types
- Relationships and foreign keys
- Constraints and defaults

### 3. API Design
- Routes and methods
- Request/response schemas
- Authentication requirements

### 4. Authentication & Authorization
- Auth provider (Supabase Auth, Clerk, etc.)
- User roles and permissions
- Session management

### 5. AI Integration
- Claude API usage patterns
- Error handling for AI calls
- Cost management strategies

### 6. Third-Party Integrations
- Payment processing (Stripe)
- Email services
- Analytics

### 7. Security Considerations
- Row Level Security (RLS)
- Input validation
- Rate limiting

### 8. Project Structure
- Folder organization
- Route groups
- Component directories

## Architecture Prompt

Start a fresh Claude Chat session for technical planning:

```markdown
Create a Solution Architecture document for [PRODUCT NAME].

Technology Stack (recommended for AI SaaS):
- Frontend: Next.js 14+ with App Router
- Styling: Tailwind CSS
- Database: Supabase (PostgreSQL + Auth + Storage)
- AI: Claude API (Anthropic)
- Payments: Stripe
- Hosting: Vercel

The Architecture document should include:
1. System Overview (architecture diagram, component responsibilities)
2. Database Schema (tables, columns, constraints, RLS policies)
3. API Design (routes, methods, request/response schemas)
4. Authentication and Authorization
5. AI Integration (prompts, error handling, cost management)
6. Third-Party Integrations
7. Security Considerations
8. Project Structure (folder organization, route groups)

Output in markdown format, ready to save as docs/architecture.md.
```

## Example: System Overview

```markdown
## System Overview

### Architecture Diagram

┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Browser   │────▶│   Vercel    │────▶│  Supabase   │
│  (Next.js)  │◀────│  Functions  │◀────│ (PostgreSQL)│
└─────────────┘     └──────┬──────┘     └─────────────┘
                           │
                    ┌──────▼──────┐
                    │  Claude API │
                    └─────────────┘

### Component Responsibilities

| Component | Responsibility |
|-----------|---------------|
| Next.js App | UI rendering, client-side state |
| API Routes | Business logic, data validation |
| Supabase | Data persistence, auth, file storage |
| Claude API | AI-powered features |
| Stripe | Payment processing |
```

## Save the Architecture Document

Save as `docs/architecture.md` so Claude Code can reference it:

```bash
mkdir -p docs
# Copy Claude's output to docs/architecture.md
```

:::tip Claude Code Integration
This file becomes part of your project's context system. Claude Code will read it when initializing your project structure.
:::
