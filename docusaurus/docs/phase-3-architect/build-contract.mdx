## What is the Build Contract?

The Build Contract consolidates your design artifacts into a single document that Claude Code can reference during implementation. It extracts the essential information from:
- Design Brief (vocabulary)
- UX Package (user model, screens)
- UI System (components)
- Architecture (data model, API)

## Build Contract Structure

### Section 1: Vocabulary
Canonical terms from Design Brief.

| Term | Definition | Usage Context |
|------|------------|---------------|
| Term 1 | Definition | Where used |
| Term 2 | Definition | Where used |

### Section 2: User Model
User types and authentication from UX Package.

### Section 3: Screen Inventory
All screens with routes from UX Package.

| Screen | Route | Purpose | Key Components |
|--------|-------|---------|----------------|
| Dashboard | /dashboard | User overview | StatsCards, ActivityList |

### Section 4: Component Specifications
Key component behaviors from UI System.

### Section 5: Data Model
Tables and relationships from Architecture.

| Table | Columns | Constraints | RLS Policy |
|-------|---------|-------------|------------|
| users | id, email, ... | FK to auth.users | Own data only |

### Section 6: API Surface
All API routes from Architecture.

| Route | Method | Purpose | Auth Required |
|-------|--------|---------|---------------|
| /api/items | GET | List items | Yes |
| /api/items | POST | Create item | Yes |

### Section 7: Quality Standards
Compiled from all documents.

## Build Contract Prompt

Start a fresh Claude Chat session:

```markdown
I need you to generate a Build Contract from my design artifacts.

Please analyze the attached design artifacts and create a Build Contract
with these sections:

1. **Vocabulary**: Extract all canonical terms from the Design Brief.
   Format as table: | Term | Definition | Usage Context |

2. **User Model**: Extract user types, auth, and flows from UX Package.

3. **Screen Inventory**: Extract all screens with routes from UI System.
   Format as table: | Screen | Route | Purpose | Key Components |

4. **Component Specifications**: Extract key component behaviors from UI System.

5. **Data Model**: Extract entities and relationships from Architecture.
   Format as table: | Table | Columns | Constraints | RLS Policy |

6. **API Surface**: Extract all API routes from Architecture.
   Format as table: | Route | Method | Purpose | Auth Required |

7. **Quality Standards**: Compile standards from all documents.

[Attach: Design Brief, UX Package, UI System, Architecture Document]

Output in markdown format, ready to save as docs/build-contract.md.
```

## Save the Build Contract

```bash
# Save to docs folder
# Copy Claude's output to docs/build-contract.md
```

:::warning Critical for Implementation
Claude Code reads files from your project. The Build Contract must be saved as a file so Claude Code can reference it during the Build phase.
:::
