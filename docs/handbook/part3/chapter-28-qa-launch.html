Chapter 28: QA and Launch Checklist

In this chapter, you'll learn the QA and launch checklist that ensures your application is production-ready. This is the final quality gate before real users see your product. By the end of this chapter, you'll have a complete launch verification workflow.

28.1 Why the Launch Phase Matters

The Launch phase ensures your application is production-ready. Skipping these checks leads to embarrassing bugs in front of real users, security vulnerabilities, and poor performance that drives users away. This phase connects all previous work — your design, architecture, and implementation — into a verified, deployable product.

28.2 How Launch Supports the Process

Launch is not just "pushing to production." It's the final quality gate that validates:

  • Design intentions are realized — UX flows work as specified
  • Architecture is sound — Performance meets requirements
  • Implementation is complete — All features work, all tests pass
  • Security is enforced — RLS policies, auth, and data protection verified

28.3 Pre-Launch Workflow

The pre-launch workflow ensures nothing critical is missed before users see your product. Work through each category systematically.

Pre-Launch Checklist

  • All tests passing, no TypeScript errors, no linting errors
  • Environment variables secured, RLS policies tested
  • Lighthouse score >= 90, Core Web Vitals passing
  • All user flows tested, mobile responsive verified
  • Error monitoring configured, analytics configured
  • Database backups enabled, domain configured

Security Verification (OWASP-Based)

Critical: Do not skip security verification. A single vulnerability can compromise all user data and destroy trust.

Authentication & Session Management

# Verify password policies (Supabase Auth settings) # Dashboard -> Authentication -> Policies # - Minimum 8 characters # - Require mix of letters/numbers recommended # Test session expiry # Verify secure cookie settings (check browser DevTools) # - HttpOnly: true # - Secure: true (HTTPS only) # - SameSite: Lax or Strict

Authorization & Access Control

# Test RLS policies by attempting unauthorized access # In Supabase SQL Editor, run as different roles: SET LOCAL ROLE anon; SELECT * FROM profiles; -- Should return empty or error SET LOCAL ROLE authenticated; SELECT * FROM profiles; -- Should only return own profile # Test horizontal and vertical privilege escalation

Input Validation & Injection Prevention

# Test for SQL injection (should be prevented by Supabase client) # Try entering in form fields: # ' OR '1'='1 # '; DROP TABLE users; -- # Test for XSS (Cross-Site Scripting) # Try entering in any text field: # <script>alert('XSS')</script> # Verify scripts do NOT execute

Security Headers

Add to next.config.js:

// next.config.js const securityHeaders = [ { key: 'X-DNS-Prefetch-Control', value: 'on' }, { key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains; preload' }, { key: 'X-Frame-Options', value: 'SAMEORIGIN' }, { key: 'X-Content-Type-Options', value: 'nosniff' }, { key: 'Referrer-Policy', value: 'origin-when-cross-origin' }, ]; module.exports = { async headers() { return [{ source: '/:path*', headers: securityHeaders }]; }, };

Performance Verification

# Run Lighthouse audit npx lighthouse http://localhost:3000 --output=html --output-path=./lighthouse-report.html # Check bundle size npm run build # Verify Core Web Vitals in Chrome DevTools # Performance tab -> Largest Contentful Paint < 2.5s # First Input Delay < 100ms # Cumulative Layout Shift < 0.1

User Flow Testing

  1. Sign up with a new email → verify email flow works
  2. Log in with credentials → redirects to dashboard
  3. Complete core feature flow → data persists correctly
  4. Test on mobile device or Chrome DevTools mobile view
  5. Test error states (wrong password, network offline, etc.)

28.4 Launch Day Actions

Launch day has its own checklist separate from pre-launch verification.

Launch Day Checklist

  • DNS configured and propagated (can take up to 48 hours)
  • SSL certificate active and verified
  • Production environment variables set in Vercel/hosting
  • Stripe webhooks configured for production URL
  • All team members have access to monitoring dashboards
  • Support channels ready (email, chat, etc.)
Post-Launch Monitoring: Monitor error rates and user behavior closely for the first 48 hours. Be prepared to roll back if critical issues emerge.

Expected Outcome

What you should have: A complete QA and launch checklist to verify before going live.

What you should do: Execute every item in the pre-launch and launch day checklists before announcing to users.
