Chapter 42: QA and Launch Checklist

In this chapter, you'll learn the QA and launch checklist that ensures your application is production-ready. This is the final quality gate before real users see your product. By the end of this chapter, you'll have a complete launch verification workflow.

42.1 Why the Launch Phase Matters

The Launch phase ensures your application is production-ready. Skipping these checks leads to embarrassing bugs in front of real users, security vulnerabilities, and poor performance that drives users away. This phase connects all previous work — your design, architecture, and implementation — into a verified, deployable product.

42.2 How Launch Supports the Process

Launch is not just "pushing to production." It's the final quality gate that validates:

  • Design intentions are realized — UX flows work as specified
  • Architecture is sound — Performance meets requirements
  • Implementation is complete — All features work, all tests pass
  • Security is enforced — RLS policies, auth, and data protection verified

42.3 Pre-Launch Workflow

The pre-launch workflow ensures nothing critical is missed before users see your product. Work through each category systematically.

DO: Code Quality

  1. Run test suite — npm test — all tests must pass
  2. Run type check — npx tsc --noEmit — no TypeScript errors
  3. Run linter — npm run lint — no linting errors
  4. Run build — npm run build — build succeeds without warnings

DO: Add Security Headers

Add to next.config.js:

// next.config.js const securityHeaders = [ { key: 'X-DNS-Prefetch-Control', value: 'on' }, { key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains; preload' }, { key: 'X-Frame-Options', value: 'SAMEORIGIN' }, { key: 'X-Content-Type-Options', value: 'nosniff' }, { key: 'Referrer-Policy', value: 'origin-when-cross-origin' }, ]; module.exports = { async headers() { return [{ source: '/:path*', headers: securityHeaders }]; }, };

Security Verification (OWASP-Based)

Critical: Do not skip security verification. A single vulnerability can compromise all user data and destroy trust.

VERIFY: Authentication & Session

  • Password policy enforced (Supabase Dashboard → Authentication → Policies)
  • Session cookies are HttpOnly, Secure, and SameSite (check browser DevTools)
  • Session expiry works correctly

DO: Test RLS Policies

Run in Supabase SQL Editor:

-- Test as anonymous user (should fail or return empty) SET LOCAL ROLE anon; SELECT * FROM profiles; -- Test as authenticated user (should only return own data) SET LOCAL ROLE authenticated; SELECT * FROM profiles;

VERIFY: Input Validation

  • SQL injection blocked — try ' OR '1'='1 in form fields
  • XSS blocked — try <script>alert('XSS')</script> in text fields
  • Scripts do NOT execute when malicious input is entered

Performance Verification

DO: Run Performance Audit

# Run Lighthouse audit npx lighthouse http://localhost:3000 --output=html --output-path=./lighthouse-report.html # Check bundle size npm run build

VERIFY: Performance Targets

  • Lighthouse score >= 90
  • Largest Contentful Paint < 2.5s
  • First Input Delay < 100ms
  • Cumulative Layout Shift < 0.1

User Flow Testing

DO: Test Critical Flows

  1. Sign up — Create account with new email, verify email flow works
  2. Log in — Sign in with credentials, confirm redirect to dashboard
  3. Core feature — Complete main user flow, verify data persists
  4. Mobile — Test on mobile device or Chrome DevTools mobile view
  5. Error states — Test wrong password, network offline, invalid input

42.4 Launch Day Actions

Launch day has its own checklist separate from pre-launch verification. Complete these items before going live.

DO: Infrastructure Setup

  1. Configure DNS — Point your domain to Vercel (add CNAME or A records)
  2. Verify SSL — Check certificate is active in browser (padlock icon)
  3. Set production env vars — In Vercel dashboard, add all production keys
  4. Configure Stripe webhooks — Update webhook URL to production domain
  5. Enable monitoring — Set up error tracking (Sentry) and analytics

VERIFY: Launch Readiness

  • DNS propagated (test with dig yourdomain.com)
  • SSL certificate shows valid in browser
  • All environment variables set (check Vercel logs for missing vars)
  • Stripe test payment works on production
  • Team members can access monitoring dashboards
  • Support email/chat channels are active
DNS Propagation: DNS changes can take up to 48 hours to propagate globally. Plan your launch accordingly and test from multiple networks.
Post-Launch Monitoring: Monitor error rates and user behavior closely for the first 48 hours. Be prepared to roll back if critical issues emerge.

Expected Outcome

What you should have: A production-ready application with all infrastructure configured.

What you should do: Execute every DO item, then verify every VERIFY item before announcing to users.
